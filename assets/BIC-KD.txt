Project Analysis: BIC (Industrial Parts Catalog)
Based on my analysis of the codebase, this is a Laravel-based e-commerce/catalog web application for an industrial parts company (likely "BIC" or similar, focused on tractor parts, earthmovers, locomotives, defence equipment, power insulators, and exclusive ranges). The project serves as a digital catalog for browsing and managing industrial components, with a public front-end for customers and an admin panel for product management.

Project Overview
Purpose: A web platform to showcase and manage industrial parts inventory, allowing users to browse products by category, subcategory, and brand model, while providing admins with tools to add, edit, and delete products with images.
Type: Full-stack web application (MVC architecture).
Domain: E-commerce/catalog for B2B industrial parts (e.g., tractor components, heavy machinery parts).
Status: Appears to be a functional prototype or MVP, with seeded data for categories like "Tractor Parts" (subcategories: Massey Ferguson, Mahindra, etc.) and sample products with part numbers and OE references.
Key Features & Functionality
Front-End (Public Site):

Landing Page: Static homepage with company branding.
Product Catalog: Hierarchical browsing (Category → Subcategory → Brand Model → Products). Displays product details like name, part numbers, OE references, and images.
Filtering & Search: Filter products by category, subcategory, and brand model.
Pagination: AJAX-based "Load More" for dynamic product loading (16 products per page).
Company Pages: Static pages for About, Meet Management, Infrastructure.
Contact Form: User-submitted contact form with email notifications (via Laravel Mail).
Responsive Design: Built with Tailwind CSS for mobile-friendly UI.
Admin Panel:

Authentication: Login/logout system for admins (using Laravel's built-in auth).
Product Management: Full CRUD (Create, Read, Update, Delete) for products, including:
Validation for required fields (e.g., name, part numbers, OE reference).
Image upload (single image per product, stored in products with metadata in database).
Association with categories, subcategories, and brand models.
Dashboard: Basic admin home with product listing by category/subcategory.
Data Model & Relationships:

Categories: Top-level (e.g., Tractor Parts, Earthmovers).
Subcategories: Belong to categories (e.g., Massey Ferguson under Tractor Parts).
Brand Models: Specific models/variants (e.g., MF 1035 DI) linked to subcategories.
Products: Core entity with part numbers, OE references, and multiple photos.
Photos: Image management with file paths, sizes, and user associations.
Users: Basic user model for admin auth.
Relationships: Eloquent ORM used for belongsTo/hasMany (e.g., Product belongs to Category/Subcategory/BrandModel, has many Photos).
Additional Features:

File Handling: Image uploads with validation (JPEG/PNG, max 2MB), storage in public directory, and cleanup on delete.
Email Notifications: Contact form sends emails via Laravel Mail (ContactMail class).
Helpers: Custom helper functions (in Helpers.php).
Caching & Artisan: Cache clearing route for development.
Seeders: Pre-populated data for categories, subcategories, and brand models (e.g., 10 subcategories under Tractor Parts).
Technology Stack
Backend: Laravel 11 (PHP 8.2), Eloquent ORM, Blade templating.
Frontend: Tailwind CSS for styling, Vite for asset bundling, Axios for AJAX requests.
Database: MySQL (via Laravel migrations), with tables for users, categories, subcategories, brand_models, products, photos.
Admin UI: Argon Dashboard (Bootstrap-based admin template).
Other Tools: Composer for PHP dependencies, PHPUnit for testing, PostCSS for CSS processing.
Deployment/Dev: XAMPP (local server), with Vite for dev builds.
