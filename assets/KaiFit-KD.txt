Project Analysis: KaiFit - Laravel-Based Fitness App Admin and Backend
Based on my analysis of the KaiFit project codebase, here's a comprehensive overview focused on the admin panel and backend APIs. This is structured to help you extract key points for your resume, highlighting technologies, features, and responsibilities you might have handled.

Project Overview
Framework & Tech Stack: Laravel (PHP framework), MySQL database, Blade templating for views, JavaScript/jQuery for frontend interactions, CSS for styling. Includes integrations with third-party services like RevenueCat (subscriptions), Canny (user feedback), Google Places API (restaurants), Firebase Cloud Messaging (FCM) for push notifications, and Make.com for lead automation.
Architecture: MVC pattern with separate admin and API controllers. Uses Sanctum for API authentication, middleware for security, and job queues for background tasks (e.g., email sending).
Database: Complex schema with 70+ tables (via migrations) handling users, food/exercise logs, subscriptions, notifications, restaurants, leads, and analytics. Includes soft deletes, enums, and relationships for data integrity.
Deployment/Environment: Runs on XAMPP (local dev), with domain-based routing for API vs. web (e.g., api.kaifit.ai).
Admin Panel Features & Responsibilities
The admin panel (under admin) provides a web interface for managing app data. Key areas include:

User Management:

View and filter users (e.g., by email, mobile, promo code) with pagination and sorting.
Block/unblock users from analytics reports (as seen in manage_users.blade.php).
Manage corporate users and codes for B2B features.
Handle user subscriptions, applied codes, and transactions.
Content Management:

CRUD for articles/blogs and categories (with tags, thumbnails, sources).
Restaurant and menu management (integrates with Google Places for data).
Notifications: Scheduled notifications with categories, subcategories, and content. Includes bulk sending and status updates.
Subscription & Marketing:

Generate and manage subscription offers/codes (with limits, lifetime options).
Beta subscriber management (waitlist signups with device tracking).
Lead management: Upload leads, send dynamic/welcome emails, bulk reminders/feedback, and email tracking.
Marketing analytics: Dashboards for subscriber stats, activation data, feature usage, and exports (CSV). Includes charts and date-range filtering.
Reports & Analytics:

Restaurant reports with Google Places integration.
User activity tracking (app usage time, steps, burned calories).
Export functionality for beta subscribers and activation data.
Settings & Corporate:

App settings (e.g., Android/iOS versions).
Corporate dashboard for managing users and generating codes.
Key Controllers: UserController, BetaSubscribersController, LeadUploadController, SubscriptionOfferController, NotificationController, ReportsController, etc. (under Admin).

Backend API Features & Responsibilities
The APIs (under api.php) power the mobile app, handling data logging, authentication, and integrations. Versioned under /v1/.

Authentication & Security:

Login via email/mobile, OTP verification, social logins (Google, Apple).
Device data storage, FCM token management for notifications.
Sanctum-based auth with refresh tokens. Secure endpoints for Make.com lead creation.
Profile & User Data:

User details, targets (e.g., macronutrients, goals), analysis (nutrient breakdowns).
Water cup tracking, sleep notifications, personalized recommendations.
Health sync data (e.g., Apple Health), weight history, allergies.
Food & Exercise Logging:

Food search/autocomplete, logging (custom, scanned via images), recipes, and meals.
Exercise logging with descriptions and burned calories.
Meal suggestions, history, and adjustments (e.g., luteal phase for women).
Quick logging, saved foods/meals, and ingredient management.
Restaurant & External Integrations:

Google Places integration for restaurant search, menus, and QR codes.
Favourite restaurants, menu classification, and food logging from menus.
Subscriptions & Payments:

Promo code validation, entitlements via RevenueCat webhooks.
Subscription user management with payload tracking.
Notifications & Analytics:

Push notifications, scheduled content, and read status.
App usage tracking, API logs for debugging.
Canny SSO for user feedback.
Other Features:

Lead creation (secured for Make.com), email OTP, self-care quotes.
Account deletion/reset with data overrides.
Key Controllers: AuthController, ProfileController, FoodLogController, SubscriptionController, RevenueCatWebhookController, etc. (under Api).

Integrated external services (RevenueCat for subscriptions, Google Places for restaurants, FCM for notifications) with secure webhooks and middleware.
